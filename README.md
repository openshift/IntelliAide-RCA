# IntelliAide-RCA

AI-assisted **root cause analysis (RCA) for OpenShift must-gather data**.

IntelliAide ingests an OpenShift must-gather archive, classifies its YAML and
log content with an ML pipeline, and drives an LLM agent workflow to produce a
structured RCA report — executive summary, chain of events, causal DAG, and
remediation guidance — exportable as PDF, DOCX, and Markdown.

> **AI-generated output.** RCA content produced by IntelliAide is generated by a
> large language model and must be reviewed by a qualified engineer before being
> acted upon or shared with a customer. See [docs/ui/AI_USAGE_NOTICE.md](docs/ui/AI_USAGE_NOTICE.md).

## Repository layout

| Path | Contents |
|---|---|
| `src/api/` | FastAPI service running the must-gather analysis / RCA workflow |
| `src/api/core/` | Orchestrator, LLM RCA agent, data analyzer, tooling, model governance |
| `src/api/machine_learning/` | Drain3-based log and YAML classification pipeline |
| `frontend/` | React (Vite + TypeScript) dashboard served by nginx |
| `k8s/` | OpenShift manifests (Namespace, ConfigMap, Deployments, Routes, RBAC, PVC) |
| `content/` | Shared UI content registry (legal documents, notices, RCA stages) |
| `docs/ui/` | User-facing guides, AI usage notice, customer content AI policy |
| `tests/` | pytest suite |

## Architecture

- **Browser → Frontend Route**: `https://<frontend-route-host>/`
- **Frontend nginx → API Service**: `/api/*` → `http://must-gather-api:8000/*` (in-cluster)
- **API** reads must-gather data from the path supplied as `must_gather_root_folder`

LLM inference uses **Claude via GCP Vertex AI** (token auth via Application
Default Credentials). Model use is constrained by the `model_governance`
allowlist/blocklist in `src/api/config/config.json`.

## Prerequisites (deployment)

- **OpenShift** cluster (manifests use `Route`; vanilla Kubernetes needs an Ingress or `oc/kubectl port-forward`)
- `oc` CLI
- A container registry reachable by the cluster
- A GCP identity with Vertex AI permissions for the configured project/model

> Image references in `k8s/api-deployment.yaml` and `k8s/frontend-deployment.yaml`
> point at development registry locations. Override them with the `API_IMAGE`
> and `FRONTEND_IMAGE` environment variables (see `k8s/deploy-openshift.sh`) or
> edit the manifests before deploying.

### Configure GCP credentials (ADC) for Vertex AI Claude

The API Deployment expects the credentials file at:

- `GOOGLE_APPLICATION_CREDENTIALS=/secrets/gcloud/application_default_credentials.json`

Create the Kubernetes Secret from your local ADC file (recommended):

```bash
gcloud auth application-default login

oc create secret generic gcloud-adc-secret \
  --namespace=must-gather \
  --from-file=application_default_credentials.json=$HOME/.config/gcloud/application_default_credentials.json
```

If the Secret already exists and you want an idempotent “apply”:

```bash
gcloud auth application-default login

oc create secret generic gcloud-adc-secret \
  --namespace=must-gather \
  --from-file=application_default_credentials.json=$HOME/.config/gcloud/application_default_credentials.json \
  --dry-run=client -o yaml | oc apply -f -
```

Notes:
- `k8s/secret.yaml` is intentionally ignored by git. A safe committed template exists at `k8s/secret.template.yaml`.
- The API code uses `google-auth` (preferred) or `gcloud auth print-access-token` (fallback) to mint a token for Vertex.

### OpenShift login, users, and OAuth

HTPasswd identity-provider setup, admin users (`ADMIN_USERS`), and the OAuth
client are managed by the helper scripts in `k8s/`:

```bash
k8s/setup-htpasswd-idp.sh    # create/refresh the HTPasswd identity provider
k8s/add-htpasswd-user.sh     # add a user to the HTPasswd secret
k8s/fix-oauth-client.sh      # reconcile the OAuthClient redirect URIs
```

Generated htpasswd files and saved credentials are gitignored and must never be
committed.

### Deploy to OpenShift (apply manifests)

Create the namespace, then the ADC Secret, then apply the app manifests:

```bash
oc apply -f k8s/namespace.yaml

oc create secret generic gcloud-adc-secret \
  --namespace=must-gather \
  --from-file=application_default_credentials.json=$HOME/.config/gcloud/application_default_credentials.json \
  --dry-run=client -o yaml | oc apply -f -

oc apply -f k8s/configmap.yaml
oc apply -f k8s/api-deployment.yaml
oc apply -f k8s/frontend-deployment.yaml
oc apply -f k8s/openshift-routes.yaml
```

Wait for rollouts:

```bash
oc rollout status deploy/must-gather-api -n must-gather
oc rollout status deploy/must-gather-frontend -n must-gather
```

### Get the Route URL and open the UI

```bash
FRONTEND_HOST="$(oc get route must-gather-frontend-route -n must-gather -o jsonpath='{.spec.host}')"
echo "https://${FRONTEND_HOST}/"
```

In production, the UI will call the API via the same host at:
- `https://<frontend-route-host>/api/health`
- `https://<frontend-route-host>/api/analyze`

That works because nginx in the frontend image proxies `/api/` to the in-cluster Service `must-gather-api`.

### Load must-gather logs into the API pod (for testing)

The API Deployment includes an `emptyDir` mounted at:
- `/data/must-gather`

Copy a must-gather folder from your workstation into the running API pod:

```bash
API_POD="$(oc get pod -n must-gather -l app=must-gather-api -o jsonpath='{.items[0].metadata.name}')"

# Example: copy a local directory named "must-gather.local.12345"
oc cp ./must-gather.local.12345 "${API_POD}:/data/must-gather/must-gather.local.12345" -n must-gather
```

Important:
- `emptyDir` is **ephemeral** (pod restart = data gone). For persistent test data, change the volume to a PVC.

### Run an analysis (API call)

The API requires `must_gather_root_folder` unless you bake a default into `src/api/config/config.json`.

Using the UI route (recommended, since it already proxies `/api`):

```bash
FRONTEND_HOST="$(oc get route must-gather-frontend-route -n must-gather -o jsonpath='{.spec.host}')"

curl -sk "https://${FRONTEND_HOST}/api/health"

curl -sk "https://${FRONTEND_HOST}/api/analyze" \
  -H 'Content-Type: application/json' \
  -d '{
    "user_query": "Why are nodes reporting NotReady after upgrade?",
    "must_gather_root_folder": "/data/must-gather/must-gather.local.12345"
  }'
```

Poll status (replace `<session_id>` with the returned id):

```bash
curl -sk "https://${FRONTEND_HOST}/api/status/<session_id>"
```

### Vertex AI / Claude settings

Cluster-side settings live in `k8s/configmap.yaml` (example values):

- `ANTHROPIC_VERTEX_PROJECT_ID`
- `CLOUD_ML_REGION`
- `ANTHROPIC_MODEL`
- `VERIFY_SSL`

The API code also ships with defaults in `src/api/config/config.json`:
- `claude.auth_type`: `gcloud`
- `claude.endpoint_pattern`: Vertex AI `rawPredict` endpoint
- `claude.model_id`: `claude-sonnet-4-6`

If you change project/region/model, update `k8s/configmap.yaml` and/or `src/api/config/config.json` and rebuild the API image.

### Troubleshooting

- Check pods/services/routes:

```bash
oc get all -n must-gather
oc get route -n must-gather
```

- API logs:

```bash
oc logs -n must-gather deploy/must-gather-api
```

- Frontend logs (nginx):

```bash
oc logs -n must-gather deploy/must-gather-frontend
```

- Validate the in-cluster reverse proxy from the frontend pod:

```bash
FRONTEND_POD="$(oc get pod -n must-gather -l app=must-gather-frontend -o jsonpath='{.items[0].metadata.name}')"
oc rsh -n must-gather "${FRONTEND_POD}" sh -lc 'wget -qO- http://must-gather-api:8000/health && echo'
```
